# Handoff and documentation skill

Use when a work package changes code, configuration, installed tools, model
state, PC .227, or PC .15.

1. Record only verified, non-secret facts.
2. Include changed paths or services, tests/verification, Git commit, running
   state, open risks, and one exact next action.
3. Write dated snapshots; update only the latest-status file owned by the
   current machine.
4. Copy cross-PC handoffs to the approved shared folder without credentials,
   raw CAD data, recordings, or large media assets.
5. Add a short `Codex catch-up` paragraph so a hosted review can resume from
   the handoff alone.
